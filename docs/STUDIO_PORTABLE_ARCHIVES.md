# Iris Studio — 单项目 ZIP 迁移（#109 A2）

## 用法
1. 进入「项目」→ 打开作品 → 右上角「⋮」→「导出项目 ZIP」；使用 Android 系统文件选择器选定保存位置。
2. 换设备后，在「项目」列表右上角选择「导入项目 ZIP」，选取原文件。导入结果将以「(imported)」命名，**不覆盖**设备已有项目。
3. 导入会复制项目内全部已引用的本地媒体、Take 候选文件和时间线音视频素材，并重新映射项目、镜头、Take、素材与轨道 ID。
4. 旧设备上的远端任务 ID 会被移除；导入时处于 running 的任务转为 failed，可手动重新规划，但**绝不会自动继续、提交或重试付费请求**。

## 安全设计
- ZIP 版本为 1，包含 `manifest.json`、`project.json` 以及按清单顺序写入的 `media/<index>.<ext>`。
- 流式复制，限制为最多 256 项媒体、单文件 1 GiB、总计 2 GiB，JSON 元数据最多 4 MiB。
- 校验目录结构、清单重复、未知条目、引用完整性、ZIP CRC 与媒体数量；不根据 ZIP 文件名创建目标路径，阻止路径穿越。
- 先导入到应用私有临时目录，再安放媒体，最后调用原 ProjectStore 原子写入索引；失败时删除本轮新媒体，保留原索引与已有项目。
- 导出只允许访问 app files/cache 及 app-specific external files/cache 根目录；不存在或不在应用目录的媒体将明确拒绝，避免生成看似成功但素材不完整的备份。
- 历史任务不会被重建；独立于本项目且未被引用的 Results/History 不包括在 ZIP 内。不是全应用数据备份。

## 验收与限制
- JVM 回归覆盖：带重复媒体路径的项目往返、时间线重定位、ID 隔离、付费任务脱钩、缺失源拒绝、ZIP 路径穿越拒绝。
- 此提交不能代替两台真实 Android 设备的迁移实测、超大媒体故障注入或 #80 的完整 120 秒成片验收。
